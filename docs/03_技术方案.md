# 03 技术方案

## 1. 总体架构（一套后端，双端复用）
```
[小程序端 原生 WXML/WXSS] ─┐
                           ├─→ 微信云开发 CloudBase（云函数 + 云数据库 + 云存储 + AI）
[网页端 Vue3 + Vite]       ─┘       ├─ 业务云函数（账本/订阅/转账/报表）
                                    ├─ Agent 编排层（意图理解→规划→执行）
                                    └─ AI 接入（混元免费额度 + DeepSeek API）
```

## 2. 技术选型（2026-09-02 已定）
| 端 | 框架 | 理由 |
|---|---|---|
| 小程序 | **原生小程序 + 云开发** | 微信官方最佳实践，AI 生成原生代码准确率最高，无跨端需求，免多层抽象 |
| 网页 | **Vue3 + Vite + CloudBase JS SDK** | 中文生态好、上手快，SDK 兼容好 |
| 后端 | **微信云开发（云函数+云数据库）** | 免费额度、免运维、双端复用同一套后端 |

### 为什么不用 uni-app / Taro
- uni-app / Taro 的价值是"一套代码编译到多端"（H5/App/各平台小程序）。本项目只需微信小程序 + 一个网页，无需多端编译。
- 多一层框架 = 多一层 bug 面，AI 生成的 uni-app/Taro 代码出错率更高，反而增加返工。
- 原生 + 云开发是官方模板，调试链路最短，2 人团队最省心。

## 3. AI 接入要点（避坑）
- **流式输出**：云函数代理不支持流式（无打字机效果）；用 wx.cloud.extend.AI 的 streamText()（基础库 ≥3.7.1）
- **混元**：小程序端对话优先走混元（成长计划免费额度，1 亿 token）
- **DeepSeek API**：走云函数服务端调用（Key 放云函数环境变量，勿暴露前端）
- **Trae**：开发期本地写代码用（积分免费调豆包/DeepSeek/千问/Kimi）

## 4. Agent 编排层设计（执行框架，核心难点）
- 分层：**意图识别 → 槽位抽取 → 规划（选工具） → 执行（调用业务云函数） → 结果汇总 → 追问/确认**
- 工具（Tools）：记一笔、查账单、出报告、识别订阅、取消订阅、AA 分账、设预算、设目标
- 记忆：短期保存最近 10 条对话；上下文持久化到 `users.assistantContext`，包含 `history`、`lastAction`、`recentActions` 和 `pendingAction`，重启后仍可继续纠正
- 信息不足：不写数据库，返回 `pendingAction`；用户补充后与前文合并再执行
- 纠正操作：`updateLast` 修改最近一次操作，`updateRecord` 按候选或最近 5 条操作中的 `recordId` 修改；`findAndUpdate` 按备注、分类、名称、相对日期搜索任意历史记录；服务端更新前校验 `_openid`
- 已覆盖：普通交易、订阅、预算、AA/共同账本交易和共同账本名称
- 日期默认：用户未提供日期时，以输入该句话的当天为默认日期
- 预算规则：总预算优先展示；设置日预算时按月天数推算月预算，设置月预算时按天推算日预算。人工与 AI 共用 budgets 数据，分类细预算作为可选扩展
- 日记规则：进入日记页时比较账目与心情数据指纹；未变化不调用 AI；每天最多更新 5 次；`diaryScheduler` 每天 23:00 对当天有数据或需要兜底的用户生成/补充最终日记；手动编辑内容不覆盖
- 模型容错：AI 请求遇到 429 时指数退避重试 3 次；今天、昨天、前天、本周、上周、本月、上月、今年和关键词消费查询提供规则解析与确定性文本兜底
- 学习规则：`users.assistantContext.preferenceRules` 持久化“满足关键词 -> 默认值”的规则；先应用更具体的个人规则和排除词，再应用一般规则，支持 ledger、category、merchant 扩展
- 查询事实约束：账单查询结果由服务端结构化数据固定生成，不让模型自由改写日期、金额和笔数
- 安全：涉及"转账/取消"等敏感操作加**二次确认**（符合"安全框架内完成"要求）

## 5. 双入口一致性

- AI 记账和人工记账共享同一套 `transactions`、`subscriptions`、`budgets` 数据。
- 账单页、订阅页通过 `ledgerService` 读写；AI 使用同一字段规范。
- AI 可以补全 `merchant/itemName/rawText/tags/memo`，人工可以继续编辑、纠错、删除。
- 用户没有共同账本时，账单页提供创建入口；创建后可通过邀请码或微信分享邀请另一人。
