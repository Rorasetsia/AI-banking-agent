# 15 第二轮功能测试清单（2026-10-08）

> 前置：重新编译前端，部署最新 `chatAgent` 和 `ledgerService`。测试记录使用“测试”关键词，便于清理。
> 反馈格式：编号 / 输入 / 实际回复 / 数据库变化 / 失败日志 / 截图。

## A. AI 学习与上下文

### A01 学习“女朋友吃饭 → 共同账本”
输入：
```text
跟女朋友吃饭都是记录在共同账单处
和女朋友吃饭花了52元
```
预期：第二条进入共同账本；`transactions` 有 `ledgerId`。

### A02 “我请”必须是个人账本
输入：
```text
我请我女朋友吃饭花了52元
```
预期：进入个人账本，保留请客、女朋友信息。

### A03 从个人账本移到共同账本
输入：
```text
和女朋友吃饭花了52元
这笔记到共同账本里
```
预期：第二条只更新第一条的 `ledgerId`，不新增第二条交易。

### A04 学习分类
输入：
```text
以后瑞幸都算餐饮
瑞幸花了20元
```
预期：第二条 category=餐饮。

### A05 消费上下文完整
输入：
```text
今天晚上和女朋友一起吃汉堡王花了52元
```
预期记录包含：
- merchant=汉堡王
- itemName=汉堡王
- tags 包含女朋友
- people 包含女朋友
- socialAction=共同用餐

### A06 请客上下文完整
输入：
```text
我请我女朋友吃饭花了52元
```
预期记录包含：
- socialAction=请客
- relationship=女朋友
- people 包含女朋友
- tags 包含请客、女朋友

### A07 缺金额后补充
输入：
```text
刚才和朋友聚餐花了
120元
```
预期：第一条不写库；第二条补成一条交易，并保留“朋友、聚餐”。

### A08 最近一笔纠错
输入：
```text
我请我女朋友吃饭花了52元
不是52，是58
```
预期：原记录金额变为 -58，请客和女朋友字段保持。

### A09 重启后纠错
1. 记录一笔测试交易。
2. 重启小程序。
3. 输入：`刚才那笔其实是65元`。
预期：原记录更新，不新增。

### A10 唯一历史搜索
输入：
```text
10月2号测试奶茶A花了18元
上周那杯测试奶茶A改成12元
```
预期：唯一匹配直接更新原记录。

### A11 多候选选择
输入：
```text
10月2号测试奶茶B花了18元
10月3号测试奶茶B花了15元
上周那杯测试奶茶B改成12元
第一个
```
预期：先返回候选，再只修改第一条。

## B. 查询与明细

### B01 今天的消费
输入：`帮我看看今天的消费`
预期：只查今天，返回支出和笔数。

### B02 昨天的午餐
输入：`昨天的午餐有记录到吗`
预期：查昨天、餐饮、关键词午餐；不能回复“要改成什么”。

### B03 上月查询
输入：`上个月消费多少`
预期：查询上月，不混淆本月。

### B04 明细查询
输入：`帮我详细列出来这个月的消费`
预期：逐笔列出日期、分类、商户/内容、金额。

### B05 明细追问继承
输入：
```text
帮我详细列出来这个月的消费
消费时间，备注，消费的什么，这些详细的呢
```
预期：第二次继承本月查询，继续返回明细。

### B06 关键词查询
输入：`上周汉堡王花了多少`
预期：查询上周，并按商户/内容筛选汉堡王。

## G. 异常与边界

### G01 非法金额
输入：`奶茶花了abc元`
预期：不写库，要求补充金额。

### G02 空账户
新账号打开账单、订阅、共同账本。
预期：显示空态，不白屏、不报错。

### G03 429
模拟或遇到 429。
预期：不显示堆栈；今天/本月/明细查询仍可返回兜底结果。

### G04 重复提交
连续发送两次同一笔测试消费。
预期：根据当前设计记录两条；若需要防重复，再增加去重策略。
