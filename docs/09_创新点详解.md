# 09 创新点详解（思考点在哪、凭什么赢）

## 0. 一条主线：先讲清"我们到底创新了什么"
普通记账 App 的三大死穴：记起来麻烦、记了不会用、记着记着就放弃。
我们的创新不是"加了个 AI 聊天框"，而是用 AI 重构记账的整条链路，一句话概括：

> 从"懒得记" → 到"不用记"（多模态自动入账）→ 到"它会主动帮你想"（对话管家 + 主动提醒）。

4 个创新点是一条链，不是 4 个孤立功能：
多模态记账(降低输入摩擦) → 对话式管家(降低操作摩擦+懂意图) → 个性化记忆(越用越准) → 主动提醒(从工具变管家)

---

## 1. 对话式财务管家（主攻，AI 赛道的核心考核点）
痛点洞察：记账最大的敌人是"麻烦"。选分类、填金额、记备注，三步以上，用户就坚持不了 7 天。
创新是什么：把"填表记账"变成"说话办事"。用户说人话，Agent 理解意图 → 自主规划 → 执行。

具体场景（答辩可直接讲）：
- "午饭和同事吃了 45，AA 一下" → 自动记一笔 45 元餐饮 + 识别 AA 意图 + 拆成每人应付
- "这月我是不是花太多了？" → Agent 自主规划：查账单、分类统计、对比上月、发现餐饮超支、主动追问"要不要设个餐饮预算？"
- 信息不全时主动追问："帮我还花呗" → "是还 500 那笔吗？几号还？"

技术落地：意图识别(NLU) → 槽位抽取(金额/分类/时间/对象) → function calling 调业务云函数 → 多轮上下文 → 主动追问/确认。
凭什么赢：普通 App 是"记录工具"，我们是"会算账、会建议的管家"，这正是大赛要求的"自然语言理解意图 + 自主规划 + 执行"三连。

---

## 2. 多模态记账（主攻：拍照小票 + 语音）
痛点洞察：手动输入是摩擦最大的环节，尤其小票、发票、转账截图。
创新是什么：拍照小票 → OCR → AI 自动拆解成结构化账目（商家/金额/日期/分类）；语音"打车花了 30"自动入账。

具体场景：聚餐拍一张小票 → 自动识别总额 + 明细 → 一键记账，还能直接接"AA 分账"。
技术落地：微信云开发 OCR 能力 / 混元多模态识别 + 语音识别，识别结果再交给 Agent 二次确认。
凭什么赢：很多 App 拍照只是"存个图"，我们做到"拍完自动入账 + 自动分类 + 能对话追问"，把记账摩擦压到接近零。

---

## 3. AI 主动性提醒（次：跨场景联动）
痛点洞察：用户不会天天开记账 App；订阅扣费、预算超支总是事后才发现。
创新是什么：从"被动工具"变"主动管家"，Agent 主动预测并提醒，而非事后通知。

具体场景（对应大赛"跨场景联动"考核）：
- 订阅快到期 → 提前 3 天提醒"某视频会员明天续费 25 元，要取消吗？"
- 这月餐饮已花 80% 预算 → 提前预警"按这个速度月底会超支 200"
- 检测到固定支出变化（房租涨了）→ 主动提醒
- 生日/纪念日 → 联动提醒（呼应大赛示例"检测我爱人生日"）

技术落地：云函数定时触发器扫描订阅/预算数据 → 生成提醒 → 订阅消息推送。
凭什么赢：普通 App 最多发"已超支"通知，我们做"还没超就预测提醒"+"多场景联动"。

---

## 4. 个性化记忆（次）
痛点洞察：通用分类不准（"瑞幸"算餐饮还是咖啡？），每人消费习惯不同。
创新是什么：AI 记住你的偏好，越用越懂你。

具体场景：你把"瑞幸"纠正到"咖啡"分类一次 → 以后自动归咖啡；记住你的常用商家、常用支付方式。
技术落地：云数据库存用户偏好 → 分类时先查偏好 → 每次纠错即学习，形成数据飞轮。
凭什么赢：规则式分类是"死的"，我们是"学习式"的，用户越用越离不开。

---

## 5. 组合打法 + 答辩话术
- 一句话定位："一个会说人话、会主动帮你管钱的 AI 财务管家。"
- 答辩逻辑：先讲"记账太难坚持"这个真实痛点 → 演示"说一句话就记账/问账" → 演示"拍照小票自动入账" → 演示"订阅到期主动提醒" → 收尾"越用越懂你"。
- 两个比赛分别强调：
  - FinTechathon：强调 Agent 的"意图理解、规划、执行"技术深度 + 安全二次确认
  - 小程序大赛：强调实用性 + 体验感（降低记账摩擦）+ 完整度
